# Football Life 브라우저 용량 검사기

이 패키지는 공개가 승인된 독립 브라우저 검사기입니다. 검사 파일과 자동 생성 로그·결과를 공개하고, 10명 파일럿을 통과한 뒤 200명 동시 플레이를 검사하는 용도로 사용합니다.

## 공개되는 파일과 대상

공개 대상은 브라우저 검사 스크립트 5개, 운영 자산 SHA-256 목록, `200/10` 검사 계획, 수동 GitHub Actions workflow, 이 README, `.gitignore`, `.gitattributes`뿐입니다. 제품 소스와 원래 저장소의 Git 이력·설정·산출물·환경 파일은 포함하지 않습니다.

대상 URL은 https://football-life.petermin7.workers.dev 입니다. 각 클라이언트는 별도 Chromium 프로세스와 임시 프로필로 새 게임을 시작하고, 실제 UI 선택·자연 진행·저장 후 프로세스 재실행을 검사합니다. 게임 상태·시간·RNG를 주입하지 않습니다.

검사 결과에는 자동 생성된 게임 저장 파일, 게임 속 이름과 경력, 스크린샷, 브라우저 요청 URL·자산 해시·오류·행동 로그, 러너 이름·boot ID·CPU·메모리 정보가 들어갑니다. 공개 저장소에서 실행하면 이 workflow 로그와 업로드한 artifact도 공개 열람 대상이 될 수 있습니다. Artifact 보존 기간은 7일입니다. 개인 계정이나 사용자의 기존 게임 저장을 사용하지 않습니다.

## 실행 순서

1. 검토한 이 파일들만 새 공개 저장소에 올립니다. 기존 비공개 저장소를 공개로 전환하지 않습니다.
2. Actions의 `Bounded independent browser capacity`에서 `Run workflow`를 선택하고 기본값 `pilot-only`로 실행합니다. push·PR·예약 실행은 없습니다.
3. 실제 러너의 vCPU가 4개 이상인지, 보이는 총 RAM이 14 GiB 이상인지 확인합니다. 약 16 GB 표준 러너를 기존 2 vCPU 러너와 구분하기 위한 검사입니다. `runner-hardware.json`과 원시 모니터 기록에 실제 정보를 보존합니다. 고급 유료 러너는 지정하지 않습니다.
4. 첫 10개 브라우저 파일럿의 전체 610초 결과, CPU·RAM 판정, 저장·재실행·자산 해시를 확인합니다. 실패하면 중단합니다.
5. 파일럿이 통과한 뒤 `cohort-200`을 수동 선택합니다. 이 실행도 10명 파일럿부터 다시 검사하며, 통과해야 20개 VM에서 각각 10개 브라우저, 총 200개 브라우저를 시작합니다. 파일럿 실패 시 본검사는 실행하지 않습니다.

VM 안의 초기 준비는 순차 실행합니다. 준비가 끝난 클라이언트는 공통 barrier에서 동시에 1배속 자연 플레이를 시작합니다. 각 활성 구간은 610초이며, 전원 관측 구간이 600초 이상 겹쳐야 통과합니다. 앱 준비 15초 제한, CPU·RAM 판정, 저장·네트워크·해시 조건은 유지합니다. 실패한 시도는 삭제하거나 성공으로 대체하지 않습니다.

## 비용과 검사 한계

공개 저장소의 표준 GitHub-hosted Linux 러너 무료 실행을 이용하도록 설계했습니다. 실제 사용 가능 여부와 동시 실행 수는 계정·저장소 정책에 따라 확인해야 합니다. 고급 러너, 유료 증설, 결제 설정 변경은 하지 않습니다. [GitHub Actions 과금 안내](https://docs.github.com/en/billing/concepts/product-billing/github-actions)를 확인하세요. Artifact 저장·다운로드·보존 정책도 별도로 확인해야 합니다.

동시 실행은 최대 20개 VM입니다. job당 25분 timeout을 적용하므로 전체 200명 실행은 최대 22개 job, 550 runner-minute의 timeout 상한을 가집니다. 자동 재시도나 자동 단계 확대는 없습니다. 브라우저 관측 트래픽에는 기존 유한 guard를 적용하며, npm·Chromium 설치 및 artifact 트래픽은 해당 카운터에 포함하지 않습니다.

200명 본 검사 통과 결과는 이 러너 구성과 관측 시점에서 실제 브라우저 200개가 조건을 충족했다는 뜻입니다. 파일럿만 통과한 결과는 200명 본 검사 통과를 뜻하지 않습니다. 서비스의 보편적인 최대 동시 사용자 수나 서버 전체 처리량을 보장하지 않습니다. 러너가 포화되면 생성기 한계로 분류하고 서비스 한계로 단정하지 않습니다.

## 로컬 검사

Node.js에서 다음 명령을 실행합니다. 첫 세 명령은 운영 접속 없이 self-check만 수행합니다.

```sh
node tests/playtest-browser.mjs --self-check
node tests/playtest-aggregate.mjs --self-check
node tests/load-monitor.mjs --self-check
```

Playwright와 로컬 Chromium을 별도로 준비한 환경에서는 `node tests/playtest-ui-regression.mjs`로 로컬 HTML 기반 UI 회귀 검사를 실행합니다. 해당 회귀 검사는 운영 URL을 열지 않습니다.

10명 표본 공통 구간은 609,038ms, 완전히 포함된 원시 CPU 607개 구간의 tick 가중 평균은 70.7740719%였습니다. 같은 607개 구간의 표본 평균은 70.6798862%이며 tick 가중 평균과 집계 방식이 다릅니다. 게임 진행 중 CPU 90% 초과가 최대 13개 연속 표본으로 나타나 기존 CPU 기준도 실패했습니다. 최소 가용 RAM은 11,876,343,808바이트였습니다. 시나리오 실패로 정식 pilot 집계 단계는 SKIPPED이며 원래 FAIL 판정을 유지합니다. 독립 감사에서도 공개 소스 pin·자산 SHA·8명의 전체 저장 복원·원시 CPU 지표를 확인했고 전체 FAIL을 유지했습니다.

10명 pilot을 통과하지 못했으므로 `cohort-200`은 실행하지 않았고 추가 재시도도 하지 않았습니다. 200명 자연 플레이와 서비스 최대 수용 인원은 미검증입니다. CPU 포화만으로 각 UI timeout의 개별 원인을 단정하지 않습니다.
